## 一、首页的设计语言（提取成可复用的规则）

OOBE 要和首页「差不多」，就得先明确首页到底在遵守什么。这些不是风格偏好，
是几条能拿来做判断的规则：

| # | 规则 | 首页的体现 |
|---|---|---|
| 1 | **不用居中元素** | 所有内容贴在四个角，中区永久留空 |
| 2 | **背景是固定的舞台，不参与叙事** | 阶梯 + 纸纹 + 暗角，无动画、无交互 |
| 3 | **一次只显示一件事** | 左下角一次只出现一个模块名 |
| 4 | **强调来自「被选中」，不是制造** | 只有当前页点被点亮，其余安静 |
| 5 | **进度用计数，不用圆点** | `01 / 03` 而非三点连线 |
| 6 | **标签在上、主体在下** | `MODULE / SELECT` → `材质转换` → `MATERIAL CONVERTER` |
| 7 | **正文最大字重 600** | 见 `dialog-spec.md` |
| 8 | **动效只有一条曲线** | 墨水揭示 + `cubic-bezier` 系列 |

**规则 1 是硬约束。** 此前已明确：「我不希望看到任何居中元素，本身就抢占焦点」。

## 二、现有 OOBE 的问题

### 2.1 违反硬约束

```
.panel-content   justify-content: center
.step-title      text-align: center
.step-desc       text-align: center
```

**整个 OOBE 是居中的** —— 与规则 1 直接冲突。

### 2.2 结构与语言

| 问题 | 说明 |
|---|---|
| 用卡片填步骤 | 步骤 2「欢迎」与步骤 5「完成」是**两张几乎一样的卡片**，只换了图标（`ri-hand-heart-line` / `ri-rocket-2-line`），中间隔着一个巨型设置页 |
| 两套进度语言 | OOBE 用 5 个圆点 + 连线；首页用 `01 / 03` |
| 两套动效语言 | OOBE 用 `startup-slide` 幻灯片；首页用墨水揭示 |
| 一屏塞满 | 步骤 4 把十几个设置塞进一屏，而用户**还没用过这个软件** |
| 数据色挂主题 token | 国旗 SVG 里混了 `var(--surface)` / `var(--danger)`，深色下英国国旗会变色 |

### 2.3 遗留的动效陷阱

`oobe-rise` 在 `.startup-top` / `.panel-content` / `.panel-nav` 三处都用了
`both`。本项目已因 fill-mode 踩坑四次：`both`/`forwards` 会永久保留末态的
`translate`，使元素成为**包含块**，破坏其后代的 `position: fixed`。

## 三、前置依赖：`--theme-color` 不跟随主题

**这是全应用的洞，不是 OOBE 的。**

实测（深色模式下）：

```
primary bg    = rgb(20, 23, 26)   ← 浅色的墨色
primary color = rgb(35, 32, 25)   ← 深色的面（正确）
元素上的 --ink = #f2efe9           ← 令牌本身正确
```

按钮的 `color` 走令牌正常，`background` 却是死的。根因：

**`--theme-color` 只有两个来源 —— `index.html:74` 硬编码 `#14171a`，以及运行时
从用户调色板注入。`[data-theme='dark']` 从未覆盖它。**

而 `src/` 里 **`var(--theme-color…)` 被引用 106 处**。即：深色模式下，全应用
106 处拿到的是一个**为浅色界面设计的深色强调色**。

### 待决：深色下的强调色策略

| 方案 | 做法 | 代价 |
|---|---|---|
| **A. 反转** | 取反相 | 自动化，但可能出怪色 |
| **B. 提亮**（倾向） | 保持色相，明度提到可用区间 | 可控，需要 HSL 转换 |
| **C. 弃用** | 深色下一律用 `--ink` | 最安全，但用户的选择白选了 |

**倾向 B**：用户选的是「颜色」，不是「明度」。保住色相就保住了他的意图，
明度是可用性问题，应当由主题决定而不是由用户猜。

### 顺带

还有 **55 处十进制 `rgb()` 字面量**（`rgb(179,38,30)`、`rgb(16,185,129)` 等
语义色）没进 token。此前扫描只认十六进制，后来补了 `rgba(255,255,255,…)`，
**又漏了 `rgb()` 这种写法**。

## 四、新设计

### 4.1 外壳：与首页同一套

```
┌──────────────────────────────────────────────────────────┐
│ [logo] 2-Pyramid                            [☀] 14:52:09 │  ← 顶部
│        多版本资源包转换器                                  │
│        v0.0.0 · 引擎就绪                                   │
│                                                          │
│                    （阶梯背景，中区留空）                    │
│                                                          │
│  ONBOARDING / STEP                                       │  ← 左下
│  01 / 03                                                 │
│  选择语言                                                  │
│  LANGUAGE                                                 │
│                                        [←] ▬·· [→]       │  ← 右下
│                                        [ 开始使用 → ]      │
└──────────────────────────────────────────────────────────┘
```

- 复用 `<StageBackdrop />`，**不新建背景**
- 四角布局，**中区永久留空**
- 步骤用 `01 / 03`，与首页同构
- 底部动作区复用首页的 `.nav-btn` / `.ticks` / `.enter`

### 4.2 五步压成三步

| 新步骤 | 原步骤 | 内容 |
|---|---|---|
| **1. 语言 + 主题** | 原 0 + 新增 | 语言二选一；**首次启动就让用户选深浅** —— 正好用上刚做的墨水切换，也是这套设计最好的自我介绍 |
| **2. 称呼** | 原 1 | 用户名输入 |
| **3. 就绪** | 原 3 精简 + 原 2/4 合并 | 只留两个真正影响首次体验的设置；「欢迎」与「完成」两张填充卡片**删除** |

**为什么砍设置**：原步骤 4 的十几个选项，用户此刻一个都没有上下文去判断。
真正需要在转换前定下的只有两件事 —— **输出位置**和**源包处理策略**（后者
涉及删文件，必须让用户知情）。其余全部留给设置页。

**为什么删除两张卡片**：它们不承载信息，只是把步骤数凑到 5。删除后
「欢迎」由第 1 步的语言问候承担，「完成」由第 3 步的「开始使用」按钮承担。

**为什么主题放在第 1 步**：深浅是用户看到界面后 3 秒内就会有的判断，问得越早
越好；而且切换本身就是一次墨水演示，比任何文案都能说明这是个什么软件。

### 4.3 动效

| 场景 | 动效 |
|---|---|
| 步骤切换 | **墨水揭示**，与主题切换同一套（`useTheme` 里的 `revealTheme` 可复用） |
| 步骤推进方向 | 上切 / 下切交替 —— 与墨水的方向随机化一致 |
| 减少动效 | 直接切，不泼 |

现有的 `startup-slide` 幻灯片**删除**。

### 4.4 需要修的遗留项

- `oobe-rise` 的 `both` → `backwards`，并确认基线无 `opacity: 0`
- 国旗 SVG 改用固定色（数据色不挂主题 token）
- 深色下主按钮不能再是「深底深字」

## 五、验收标准

改完后必须逐条验证，不能只看截图：

1. **无居中**：量 `.panel-content` / 标题 / 描述的 `text-align` 与 `justify-content`
2. **深浅两套都可用**：每一步在 `#f4f2ee` 与 `#1a1815` 两种底色下截图比对
3. **对比度**：所有正文 ≥ 4.5:1，弱文本 ≥ 3:1（WCAG AA）
4. **无 fill-mode 残留**：切换完成后 `getComputedStyle(...).translate` 为 `none`
5. **墨水切换**：步骤切换时量三个扫描线的前沿位置，确认是不规则前沿
6. **计数正确**：`01 / 03` 在每一步都正确
7. **减少动效**：`motion-reduced` 下无动画
8. **配置写入**：走完 OOBE 后 `settings.json` 里 `initialized` / `user_name` /
   `language` / `theme_mode` 都已落盘
