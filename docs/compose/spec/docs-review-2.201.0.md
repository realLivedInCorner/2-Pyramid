| 代号 | 标准 | 判定方式 |

### 3.1 语言文件

**标点规范化（第一轮 46 处 + 收尾 2 处 + 第三轮 16 处）**

中文值里混入半角标点，与同文件既有的全角用法自相矛盾：

- 半角冒号约 30 处（`当前称呼: {name}`、各 `…失败: {error}`、`conversion.batchProgress` 等）→ 全角
- 半角句末标点（`删除原资源包?`、`文件较多,可能…`、`打包成功! 输出至:`）→ 全角
- 半角括号 6 处（`待处理队列 ({count})` 对同文件 `全部导入项（{count}）`）→ 全角
- 半角双引号 5 处（`项目 "{name}"`）→ 「」
- 全角标点后遗留的半角空格 2 处
- 省略号风格混用（`...` 与 `…`）→ 统一

## 六、本次检查的执行方式

- **三方独立校对**：语言文件、legal、README/CHANGELOG 各由一名校对员独立完成，**只读不改**；改动由主流程在核实后执行。
- **所有改动先对代码核实**：例如「白名单含子域」是打开 `updater.rs` 逐行确认后才改的；「转换路径无功能改动」是用 `git diff` 对特定目录验证输出为空才写进 CHANGELOG 的。
- **改了但验证不通过的要撤回**：第一轮标点修复后有 2 处遗留多余空格，第二轮把它当新问题再修；第一轮删掉问候语导致「**再**完成几个设置…」的「再」失去前指，同样是先做过再修的。
- **报错不成立的项也记录**（第四节），避免下一版重复排查。
- **机器核验必须每轮重跑**：见下。

### 6.1 机器核验抓住的一次人工错误（值得记下）

采纳校对建议「英文 `settings.devMode.exportActionsSuccess` 漏译『动作』」时，把值从

```
Exported {count} records: {path}
```

改成了

```
Exported {count} action records        ← {path} 被一起删掉了
```

而调用处是 `t('settings.devMode.exportActionsSuccess', { count, path: dest })`（`SettingsPage.vue:1240`）——
**英文用户会看不到导出路径**。这是「按建议改文案」时顺手删掉占位符的典型失误，
靠读文本发现不了，是每轮结尾重跑占位符一致性检查时抓出来的。

教训：**键值里的 `{...}` 是接口，不是文案**。改文案的任何一轮，都要重跑
「逐键比对占位符名称与数量」这一步。
