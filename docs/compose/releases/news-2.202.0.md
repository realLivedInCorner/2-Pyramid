# 2.202.0

> 本次主题：**资源包跨到 1.21.4+ 之后不再丢外观**。新增 1.21.4+ 物品模型定义生成，
> 并把 OptiFine CIT 迁移进同一套定义；安装器界面按主程序的骨架重做。

## 主要变化

### 1.21.4+ 物品模型定义

从 1.21.4（`pack_format` 46）起，Minecraft 通过 `assets/<命名空间>/items/<名称>.json` 的**物品模型定义**决定物品外观，取代了原先写在 `models/item/*.json` 里的 `overrides` 与 `CustomModelData` 谓词。

**这意味着旧包转到 1.21.4+ 后，所有自定义外观会静默消失** —— 没有报错、没有警告，就是不见了。本版之前，本程序对物品定义没有任何概念。

新增任务 `generate_item_definitions`（架构师阶段，版本边 `(42,46)`），把 `overrides` + `CustomModelData` 迁移成物品定义。

参考数据**从官方客户端 jar 直接提取**，不是抄录：本机装着的 1.21.4 / 1.21.8 / 1.21.10 / 1.21.11 / 26.2 五份 jar，脚本读取每份 jar 自报的 `pack_version.resource` 而非写死格式号，并把 jar 的 SHA-256 记进产物。5 档共 **560 条定义**，488 KB。两次运行产物**逐字节相同**。

### OptiFine CIT 迁移

新增任务 `generate_cit_item_definitions`（外科医生阶段，版本边 `(46,55)`），把 OptiFine 的 CIT 规则（`optifine/cit/**` 与 `mcpatcher/cit/**`）转成物品定义里的 `select` 分支。

- `nbt.CustomModelData=N` → 按 `custom_model_data` 选择，`when: N`
- `texture=` → 生成模型，**并把贴图搬进 `textures/cit/`**（CIT 贴图在原位客户端不会索引，这一步是必须的）
- `model=` → 直接引用

**翻不了的条件如实跳过并记录**：`damage=`、`enchantments=`、任意 `nbt.*`、无条件换皮。把精确条件放宽成近似条件，比不转换更糟。

### 修掉一个一直存在的驱动 bug

物品定义任务与既有的着色器适配任务一样，从包里的 `pack.mcmeta` 读**目标**格式。原先的注释论证这样做安全，理由是「收尾步骤会把同一个 `target_version` 写进 `pack.mcmeta`」。

**那段论证不成立** —— 写 `pack.mcmeta` 的收尾回调在**全部任务之后**才跑，所以任务执行期间包里仍是**源格式**。

这个问题是端到端用例抓到的：源 34 / 目标 55 时，任务读到 34，走了 `target < 46` 分支，**产物一个 `items/*.json` 都没有，全程零错误零警告**。

已改为开包之后、跑任何任务之前，把 `pack.mcmeta` 一次性定成目标格式。**产物不变**，由冻结内容基线把关（4018 条目 / `0x75bb3260e7f578a6`）。

顺带说明：着色器适配此前一直读的是源格式，只是参考包没有 `shaders/`（第一个判断就返回），所以从未暴露。

### 安装器界面重做

安装器是用户见到的第一个界面，此前读起来像另一个产品。

- **窗口 1200×750 → 880×680**。每一屏都是单列表单，1200 宽时 640px 的面板两侧各空 280px（**46% 面积是空的**）。两栏方案被否掉了：左栏只能放品牌加一行计数，五步里有三步是空的，而且主程序本身没有侧栏。
- **骨架与 OOBE 对齐**：阶梯背景、左上品牌、居中主体（引导词 + `01 / 05` 计数）＋ 620px 内容列 ＋ 底部药丸导航。五圆点连线已移除。
- **排版**：字重上限 600（原先 10 处 700/800）；中文标题负字距归零（26px/800/−0.5px → 32px/600/0）；三处带投影与 `backdrop-filter` 的玻璃卡片改成「行 + 发丝线」。

修掉的缺陷（都在安装器内）：

- **logo 是一团灰雾**：`stroke-width="7"` 没带 `vector-effect: non-scaling-stroke`，在 40px 尺寸下实际只有 **0.43px**。
- **加载图标从来不转**：remixicon 4.6 根本没有 `ri-spin` 这个类（只出字形、不出关键帧），所以每一个「安装中…」旁边的图标都是**静止**的，看起来像卡死。
- **安装失败后无路可走**：重试按钮写在恒假的分支里从未渲染，且失败时标题仍是「正在安装」、底部是禁用的按钮，**唯一出口是关窗口**。现在标题随失败切换，错误块给出返回，底部按钮文案同步。
- **完成屏渲染出一个空药丸**：底部那串条件在最后一步全部落空，只剩一块 14px 高的圆角底板。
- **文案事实错误**：「26 个 Minecraft 版本目标」实为 **27 个**（26 个 Java 档 + Bedrock）；「约几十 MB」改为实测的「约 10 MB」（`payload.zip` 10,265,024 字节）。

**对比度是量的，不是估的** —— 底色从截图采样（舞台是渐变，按 `--bg` 手算会得到纸面对、屏幕不对的数字）。这推翻了两个初判：深色下 `--ink-3` 在舞台上只有 4.06–4.45、`--ink-4` 只有 2.68–3.38，都不达标，于是 5 处句子升到 `--ink-2`、4 处标签升到 `--ink-3`；卸载按钮原为红字压红底，深色仅 **3.84**，改成墨色字配红色图标与描边。

## 已知边界

「支持任意两个版本之间相互转换」有四处例外：GUI 图集切分、马匹界面、叠加图标、副手槽**只做正向，降级时不还原**（反向任务是显式空操作，因为无法从产物反推原状）。跨 1.20.2 边界降级的包，这几处会保留新版形态。

OptiFine CIT 的贴图搜索顺序按老包写法惯例实现（同目录相对路径 → 旧式 `textures/items/` 变体），**无权威文档可核对**，找不到就跳过整条规则。

`custom_model_data` 组件读 `main` 字段这一条**未经客户端实测** —— 官方数据里不含该属性（Mojang 自己不用它），是从组件化知识确认的。
